# Week 2 local verification and timing diagnostics — 28 October 2026

OpenSSL 4.1.0 client and `s_server`, Windows loopback `127.0.0.1`, TLS 1.3, a freshly generated self-signed `localhost` certificate explicitly supplied as the client trust anchor; no client certificate or authorization service. Private keys and session secrets are not included here. The server was started with `s_server -accept 127.0.0.1:19523 -cert <cert> -key <key> -tls1_3 -groups X25519:X25519MLKEM768 -www`; for the wrong-group test it was restricted to `X25519`. Generate new, ephemeral test credentials in a new private temporary directory before repeating.

[results.json](results.json) contains verification results for both positive cases and wrong-name, untrusted-CA and wrong-group negative cases, along with process timings. The two matching cases completed with validated peer name and exact groups. Wrong name failed with hostname mismatch; an unrelated self-signed trust anchor failed chain validation; hybrid against the X25519-only server failed the handshake. The negative results are not successful connections.

[session-control.json](session-control.json) includes only selected status lines from OpenSSL normal output, never session keys. Normal output displayed `New` for both modes. Attempted `-reconnect` also displayed `New` for every connection on this server, so a genuinely resumed TLS 1.3 control was not obtained. The production harness still uses brief output and reports session reuse as unknown; no session status has been inferred from process creation or the control. Normal output may contain session secrets and must not be retained wholesale.

[timing-milestones.json](timing-milestones.json) records three separate TCP probes and three process runs. The OpenSSL version process was approximately 20–21 ms; TCP probes 10–16 ms; verified group output appeared 27–31 ms after client launch; `DONE` appeared about 1,000 ms later and exit about 3–5 ms after `DONE`. These are line-observation and whole-process times, not additive cost components or isolated TLS handshake timings. The cause of the delay was not established. Adding `-no_ign_eof` did not remove the delay in three trials.

All results are diagnostic smoke evidence, not an Envoy or valid performance comparison. The certificate and key paths recorded in JSON are ephemeral local paths and will not necessarily be reusable.
