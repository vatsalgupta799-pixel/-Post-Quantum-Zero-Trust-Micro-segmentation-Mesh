# Local TLS 1.3 session controls

On 28 October 2026, local OpenSSL 4.1.0 `s_server -tls1_3 -groups X25519:X25519MLKEM768 -num_tickets 2 -www` used a fresh localhost certificate explicitly trusted by the client. For each group, the client made a hostname-validated initial connection, sent a short HTTP request, received a ticket with `-sess_out`, then reconnected with `-sess_in`. OpenSSL reported `New, TLSv1.3` on both initial and separately new connections and `Reused, TLSv1.3` on the second connection, with exit 0. `session-control.json` contains only selected non-secret status lines. `ticket_file_created` records file existence at that step; it does not claim a separately created ticket for the standalone-new connection. The temporary session files were removed after use and are not included.

`patched-verifier-final.json` records final verifier positive cases and hostname/CA negative cases. `patched-wrong-group-fixed.json` records a hybrid request against an X25519-only server failing closed. `patched-wrong-group.json` is the earlier diagnostic in which OpenSSL printed `Verification: OK` despite a failed handshake; that misleading flag was fixed and the failing attempt was never accepted. `client-options.json` documents three trials each of default, `-no-interactive`, and `-nocommands`, all around one second.

The benchmark parses only OpenSSL `New`/`Reused` TLS 1.3 status and stores a boolean-compatible `session_reused` field; ambiguous, missing or failed-client status becomes unknown. The analyzer rejects resumed or unknown rows. Normal client output can contain sensitive session material; it is captured temporarily in memory and only explicitly allowlisted, non-secret verification lines are retained. Never save unfiltered session output or session files.

The historical paired experiment driver in this directory shows the exact process and output paths. To reproduce without overwriting, copy it and change its temporary directory, output directory and port to new values. It creates a self-signed certificate and key in an ignored `.tmp` directory; manage those local files privately. See the paired-results README for limits and analysis.
