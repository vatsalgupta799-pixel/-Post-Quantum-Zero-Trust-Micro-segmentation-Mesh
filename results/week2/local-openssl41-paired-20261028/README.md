# Local OpenSSL TLS process-duration experiment

OpenSSL 4.1.0 client and server on Windows IPv4 loopback, ephemeral trusted `localhost` certificate, no client certificate, no Envoy or authorization. The four measured blocks ran hybrid/classical/classical/hybrid; each had one preflight, five excluded warm-ups, and 50 measured attempts. Every preflight, warm-up and measured attempt succeeded; all 200 measured rows directly report TLS 1.3, a validated certificate, the exact mode group and OpenSSL `New` session status. See block metadata for separate preflights and warm-ups, and `classical/raw.csv` and `hybrid/raw.csv` for combined rows.

Each duration covers the Python verifier from before OpenSSL process launch until output capture, exit and parsing complete. It includes startup, TCP, TLS, verification and shutdown; it does not isolate handshake latency. One hundred samples per mode were collected rather than 1,000 because a process took about one second and 1,000 per mode would take about 35 minutes. p95/p99 and relative differences are exploratory; process shutdown dominates and cannot support a conclusion about hybrid handshake overhead. Sequential blocks in both orders reduce, but do not eliminate, time and ordering bias.

`comparison-final/` contains the final report, summary and accurately labelled charts; `comparison/` is an earlier preliminary analysis retained for provenance. `independent-check.json` independently recalculates summary statistics from the raw rows. The checked-in driver under `evidence/week2-session-control-20261028/paired-experiment-driver.py` records the exact run procedure; to repeat it, copy and change its temporary directory, port and output directory to unused values. It refuses to overwrite its original paths. Private key material was kept under the ignored temporary directory and is not included here.

Results were measured at base commit 5e5f952 with uncommitted per-sample session telemetry changes; the subsequent fix affects only failed connection flags and did not change the 200 successful observations. This is a local process-duration comparison, not an Envoy, mTLS or production network benchmark.
